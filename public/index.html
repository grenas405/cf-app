02 · The stack

Three tools. One workflow.

You don't need a server room, a DevOps team or a big budget. You need a place to run code, trustworthy parts to build it from, and a capable pair of hands. Tap a card to see where each one lives in this codebase.

Where it runs

Cloudflare Workers

  • Your code runs in Cloudflare data centers worldwide, Oklahoma City included, close to every customer.
  • Lightweight V8 isolates start in milliseconds. No servers to patch, scale or babysit.
  • The Free plan covers 100,000 requests a day, and static asset requests are free.

In this repo → src/adapters/cloudflare/worker.ts

What it's built from

JSR

  • An open-source registry for modern TypeScript and JavaScript packages.
  • Packages ship with types and docs, and work in Deno, Node, Bun, browsers and Workers.
  • Publishing from GitHub Actions adds provenance: proof of which source built the package.

In this repo → deno.json imports @std/http and @zod/zod, and the core itself passes deno publish --dry-run

How it gets built

Claude Code

  • An agentic coding tool that works in your terminal, your IDE and the browser.
  • It reads the codebase and its CLAUDE.md, edits files, runs the tests and explains the diff.
  • You approve the plan and review the change; it does the typing.

In this repo → CLAUDE.md

                08 · Claude Code

                You decide. Claude types.

                Clear rules make a codebase easy for people and for AI. Claude Code reads CLAUDE.md, follows the architecture, and proves its work with the same deno task check you would run.

                claude · ~/okc-edge illustrative session

                Why this repo is easy to delegate

                • Rules in writing. CLAUDE.md states the architecture in plain sentences.
                • Rules in code. Architecture tests fail the build if the core imports a runtime API or anything grows a class.
                • Small, pure pieces. A function with no side effects is easy to read, test and change safely.
                • One command of truth. deno task check runs format, lint, types, tests and the build.

                09 · Ship it

                From clone to live in four commands.

                1. 1deno task devBuild, then serve with the Deno adapter and std/http/file-server on localhost:8000.
                2. 2deno task dev:cfThe same build inside workerd, Cloudflare's runtime, via Wrangler.
                3. 3deno task checkFormat, lint, type-check, test and enforce the architecture rules.
                4. 4deno task deployCheck everything, then ship to Cloudflare Workers.

                Big-city infrastructure, Oklahoma-sized bill.
